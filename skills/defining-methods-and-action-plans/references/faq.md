# FAQ: Defining V2MOM Methods and Action Plans

## How many methods should a V2MOM have?

Three to six is a common range for a team or company. The number matters less than whether the team can actually resource every method on the list. If the bottom items will not get people or budget this period, move them to a "not this period" list so the choice is explicit.

## What is the difference between a method and an action?

A method is an initiative that changes something toward the vision, such as launching self-serve onboarding. An action is a concrete step under it, such as drafting the onboarding flow or interviewing new customers. Methods go in the V2MOM's main list. Actions go underneath as a short plan and change more often.

## How do I rank methods when several seem equally important?

Ask which method contributes most to the vision, and use the ranked values to break ties. Then ask the practical question: if only one of these gets the team's best engineer next month, which one? If the group still cannot decide, the V2MOM owner makes the call and records the reason.

## Should every team method map to a company method?

Most of them should, because that link is how the cascade produces alignment. A team can reasonably add one method for its own health, such as fixing a reliability problem or improving hiring, as long as it is labelled that way. If several team methods map to nothing above them, raise it with the parent owner, since either the team is drifting or the parent V2MOM is missing something.

## How detailed should action plans be?

Detailed enough that the owner can start this month, and no more. A short list of first steps, each with an owner and a rough time frame, is usually enough. Longer plans belong in a project tool and can be linked from the method.
