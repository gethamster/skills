# Examples: Enforcing Typography and Spacing Standards in AI UI

## Replacing default fonts on a product landing page

**Scenario:**

Illustrative scenario: a small team uses a coding agent to build the landing page for a note-taking app. The first draft uses Inter everywhere, five heading sizes, body text that spans the full container, and the same vertical padding on all six sections. The brand already licenses a geometric sans for its logo.

**Walkthrough:**

The team lists what the agent chose: one font, seven sizes, two weights, and one padding value. They write a typography section naming the licensed sans for display and body, a mono face for keyboard shortcuts, and four size roles: display, section heading, body and label. They cap body width with a character-based max width, allow regular, medium and semibold weights, and assign a larger spacing step between sections than inside them. On the next run the page uses four sizes, headings carry weight as well as size, and sections read as distinct blocks. One label still used a size outside the list, so they added "labels use the label size only" and the following run stayed inside the rules.

## Keeping a serif brand when the default skill discourages serifs

**Scenario:**

Illustrative scenario: a bookshop redesigns its site with the Taste Skill default installed. The brand wordmark and print catalogue both use a serif, but the skill discourages serif display type unless the brief justifies it, and the agent keeps switching headlines to a sans.

**Walkthrough:**

The team reads the serif rule and sees that it allows serifs when the brand brief names one. They add a line to their brief and to the local copy of the skill: "Display type uses the brand serif; body uses the paired sans." They keep the rest of the typography section, including the italic descender rule, because their headlines use italic emphasis. The agent now keeps the serif, and the reviewer checks that emphasis uses italic of the same family, as the default skill recommends, rather than mixing a third face.

## Tightening spacing on a pricing section

**Scenario:**

Illustrative scenario: a pricing section generated by an agent has cards with equal padding on all sides, feature lists that start at different heights, and buttons that land at random positions because each card has a different amount of text.

**Walkthrough:**

The team adds three spacing rules: card padding uses one named step, feature lists start at the same vertical position across cards, and buttons pin to the bottom of each card. The last two come from the alignment checks in the Taste Skill redesign companion. They also require that the gap between cards is larger than the padding inside them. After regeneration the cards align, and the reviewer can verify each rule by inspecting three class names instead of judging the section by eye.
