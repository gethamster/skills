# FAQ: Story Map Backbone: Identifying User Activities

## What is the difference between an activity and a user task?

An activity is a broad goal that groups several tasks, such as managing email. A user task is a short verb phrase for something the user does, such as reading or deleting a message. Jeff Patton's quick reference says activities organize tasks done by similar people at similar times toward a goal. On the map, activities sit on top and the tasks that make them up sit in the row below.

## Should the backbone contain activities, tasks, or both?

Patton's quick reference describes the backbone as the activities and tasks at a higher goal level, arranged in narrative flow. A common layout shows both rows: activities as headings and high-level tasks beneath them. Smaller sub-tasks, details and variations hang below as the ribs. Either way, the top of the map should read as the whole story.

## What order do I use when users can do things in any order?

Use the order you would use to explain the product to someone else. Patton's advice is that this explanatory order is the correct one, because the map exists to help you tell a story. Variations in order are real, and you handle them in conversation. If you need an exact process model, a flow chart suits that job better.

## Can I build a backbone for an existing product?

Yes. Patton notes that an existing product already has a backbone, and he still identifies it to see where new features fit. For adding a few features to a large product, he sometimes builds a small map per feature instead of mapping everything. Mapping how users work today is also useful, because you can mark pains and opportunities on the current story before mapping the future one.

## Who should help build the backbone?

People who know the users and their work should be there, along with at least one developer and someone who understands the business. Walk the finished backbone with a real user if you can, because users are quick to point out missing steps. A backbone written by one person tends to reflect that person's view of the product.
