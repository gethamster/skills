# FAQ: How to Write Key Results

## Can a key result be a milestone, such as a launch?

It can, but it is usually weaker than an outcome. Google's playbook treats "Launch X" with no success criteria as a classic low-value key result and suggests attaching the effect the launch should have. Binary milestones also grade as either 0 or 1, which gives less information than a measured outcome. Use them when the delivery itself is the commitment, and pair them with an outcome where you can.

## What if we do not have a baseline yet?

Make measuring it the first piece of work. A key result can state that the team will establish the baseline in the first weeks and then set a target relative to it, but only if the cycle is long enough to act on it. If the metric cannot be measured at all this cycle, it is not ready to be a key result.

## How many key results should each objective have?

Google's re:Work guide suggests around three, and What Matters says three to five. The number matters less than sufficiency: the set should prove the objective, and each key result should add something the others do not. If you need many more, the objective may be too broad.

## Should key results be leading or lagging indicators?

A mix works best. What Matters points out that lagging measures such as revenue only tell you whether you were on track after the cycle is over. Leading indicators, such as qualified meetings or activation in the first week, give the team a signal at check-ins. Keep at least one lagging measure when it is the result the objective actually cares about.

## How ambitious should a key result target be?

It depends on the OKR's label. For a committed OKR, the target should be one the team will adjust resources to hit in full. For an aspirational OKR, it can be set where success is uncertain, since Google expects an average score around 0.7 on those. Decide the label first, then set the distance.
