# FAQ: Designing Validated Learning Experiments

## What counts as validated learning in Lean Startup?

Validated learning is a conclusion about customers backed by observed behavior from a test designed in advance. The design matters as much as the data: without a stated hypothesis and threshold, a result can be read to support almost anything. A useful check is whether the result changed a decision, such as what to build, whom to target or whether to pivot.

## How is a falsifiable hypothesis different from an assumption?

An assumption is a belief the plan depends on, such as "clinics will pay for scheduling." A falsifiable hypothesis turns that belief into a measurable prediction with a segment, an action, a rate and a time window. The difference is that a hypothesis names a result that would prove it wrong. That is what lets an experiment produce a clear answer.

## When should I use an A/B test instead of a simpler experiment?

Use an A/B test when you have enough traffic to split users and reach your planned sample in a reasonable time. It is the cleanest way to attribute a change in behavior to a specific change in the product. Before you have that traffic, a landing page, manual service or prototype that produces the target behavior is usually faster and cheaper.

## How do I pick a success threshold without historical data?

Work backward from viability: estimate the conversion, retention or price the business needs to survive, and set the pass line there. Set a lower fail line and treat the gap as an inconclusive band that triggers a retest. Once you have a baseline from real customers, later thresholds can be set relative to it.

## How many experiments should run at once?

Run as many as you can while keeping each one testing a single assumption with its own audience and metric. Overlapping tests on the same users can contaminate each other, making it unclear which change caused a result. Many small teams do best running one experiment per risky assumption and finishing it before starting the next.
