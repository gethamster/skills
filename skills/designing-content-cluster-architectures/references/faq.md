# FAQ: Designing Content Cluster Architectures

## What is a content cluster architecture?

It is the structure of one topic on a site: a broad pillar page, supporting pages that each cover one subtopic in depth, and the internal links between them. It is also called the hub and spoke content model, with the pillar as the hub.

## How long should a pillar page be?

As long as it takes to cover the topic broadly and point to each supporting page. Google says it has no preferred word count, so length is not a target. If the pillar starts going deep on one subtopic, move that detail to a supporting page.

## Should supporting pages link to each other?

Yes, where a reader of one page will need the other next. Follow the reader's path through the topic. Linking every page to every other page adds clutter without helping readers.

## Do I need to move old pages into a new URL folder?

Not always. A shared folder helps organization and measurement, but moving pages that already rank creates redirects and risk. Fixing the internal links often gives most of the benefit without moving anything.

## How does the architecture change over time?

Add supporting pages as new subtopics appear, link them from the matching pillar section, and update the blueprint. When two pages start serving the same intent, merge them. Review the blueprint whenever the keyword map changes.
