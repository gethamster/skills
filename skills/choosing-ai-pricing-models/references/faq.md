# FAQ: Choosing Between AI Pricing Models

## How do I choose without production usage data?

Use pilot or beta data and label every score that depends on it as provisional. Where you have nothing, run a structured set of realistic tasks to estimate cost per value unit and its spread. Favor a model that can be adjusted without re-contracting, such as a subscription with included usage, and plan to re-score once real usage arrives.

## What if two models score almost the same?

Look at which criterion separates them and ask which one you trust more. If one model wins only on a score built from thin data, prefer the other. You can also run both for different segments, such as usage pricing for self-serve and a committed hybrid for enterprise, as long as each segment sees only one model.

## Can different segments use different models?

Yes, and it is common. Self-serve buyers often accept metering, while enterprise buyers need commitments and caps. Keep the value unit the same across segments so the models are comparable, and make sure a customer moving between segments has a clear path.

## Why does the recommendation keep changing when stakeholders weigh in?

Usually because the weights were not agreed first, so each stakeholder argues for the weights that favor their preferred model. Fix the weights in a short meeting before anyone sees scores. Then disagreements become questions about data, which are easier to settle.

## How do I price AI inside an existing non-AI product?

Score the AI features on their own. If their cost is small and even across customers, bundling them into the existing plans is usually right. If cost varies widely, consider an add-on or a usage component for the heavy features while leaving the core product priced as before.
