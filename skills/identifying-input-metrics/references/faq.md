# FAQ: Identifying and Mapping North Star Input Metrics

## What is the difference between an input metric and a KPI?

An input metric is a KPI with a specific job: it is one of the few factors that produce the North Star, and a team can move it directly. Many KPIs are not inputs. Some monitor health, such as error rates or support volume, and some report results, such as revenue. An input earns its place on the map by having a believable link to the North Star and an owner.

## How many input metrics should we have?

Few enough that each has an owner and the whole set fits on one slide. Amplitude recommends three to five influential, complementary factors. If you have more, check whether some are duplicates or sub-inputs of others. If you have fewer, check whether the map ignores part of the path to value, such as retention.

## Can one team own several inputs?

Yes, when the team is large enough or the inputs are closely related. The risk is spreading effort so thin that none of the inputs moves. If a team owns more than one, ask it to name which input it is focusing on this cycle and why.

## What if we cannot measure an input yet?

Name it, define it in words, and write down a proxy you can measure now. Amplitude's playbook shows an input map with one input marked as qualitative for the time being. Plan the instrumentation work and put it on the roadmap. An unmeasured input is still useful for planning, as long as everyone knows it is unmeasured.

## How do we know an input really drives the North Star?

You build confidence over time. Historical data shows whether the input moved before the North Star did. Experiments that move the input give stronger evidence. Keep a confidence rating on each link and revisit the weakest links first, because they are the most likely to be pulling effort in the wrong direction.
