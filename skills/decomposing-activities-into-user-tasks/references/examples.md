# Examples: Story Map Decomposition: Activities to User Tasks

## Decomposing "Pay for my order" in a food ordering app

**Scenario:**

Illustrative scenario: a team has a backbone for a restaurant ordering app. The activity "Pay for my order" has two high-level tasks under it: "review my order" and "pay."

**Walkthrough:**

Under "pay," the team adds sub-tasks: choose a payment method, enter card details, confirm payment, see a receipt. Asking what else users might do produces alternatives: pay with a saved card, pay with a digital wallet, split the bill. Asking what could go wrong produces exceptions: card declined, payment times out, user closes the app mid-payment. Details go at the bottom: which card types are accepted and what the receipt shows.

The team then writes story titles. "Pay with a saved card so that I can pay for my order quickly" is one. The column now shows a simple path at the top (enter card details, confirm, see receipt) and richer options below it, ready for slicing.

## Rescuing a column full of technical tasks

**Scenario:**

Illustrative scenario: under the activity "Get my reports," a team's cards read: build reporting service, create report tables, add export library, design report page.

**Walkthrough:**

The facilitator asks what the user does. The group rewrites the column as user tasks: choose a report, set the date range, view the report, export it. The technical cards are attached to the stories they support. When the team splits "view the report," it uses data variations: first a single standard report, then filters, then custom reports. The simplest version sits highest in the column.

## Keeping the epic in place

**Scenario:**

Illustrative scenario: a team that moved from a backlog tool to a story map habitually deletes a large story once it has been split.

**Walkthrough:**

On the map, the team leaves "Set up my team workspace" at the top of its column and hangs the split stories below: create a workspace, invite teammates by email, set roles, import existing projects. When a stakeholder later asks why "set roles" matters, the answer is visible in the card above it. The team's backlog items link back to the column so the context survives the move into the delivery tool.
