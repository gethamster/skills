# FAQ: Building Business Systems as the E-Myth Manager Role

## What does the Manager role mean in the E-Myth?

It is the part of the owner that plans, organizes and creates order and predictability. Where the Technician does the work and the Entrepreneur sets direction, the Manager builds the systems that let others do the work consistently. In most small businesses nobody fills this role deliberately, which is why processes live in the founder's head.

## Which task should I systematize first?

Pick a task that happens often, changes little and causes visible problems when done inconsistently. Client onboarding, invoicing and opening or closing routines are common first choices. Leave the most judgment-heavy work until you have practiced the format on simpler tasks.

## How detailed should a system document be?

Detailed enough that a competent person who has never done the task can run it to your standard. That usually means steps written at the level of decisions, a short checklist for the routine part and a list of exceptions. If the document runs past a couple of pages, split it into smaller systems.

## Won't systems make the work rigid?

Systems remove routine choices so the result is consistent, which leaves more attention for the parts that need judgment. The person running a system should be able to suggest improvements, and the owner should update the document when a better way is proven. A system nobody is allowed to change goes stale and gets ignored.

## How do I keep systems up to date?

Give each system an owner and a review date. Update the document whenever someone has to ask a question it should have answered or an exception repeats. Treat the operations manual as the first place to look when something goes wrong.
