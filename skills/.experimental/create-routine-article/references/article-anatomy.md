# Article Anatomy — Routine Announcement Format

The skill-launch skeleton (from dexhorthy's show-me piece) with the routine spine. Eight sections. Lowercase casual headers. Visual tour with connective prose.

## Section-by-section

### 1. tl;dr block

One sentence stating the shift from manual to automatic, then the get-it block (real tryhamster.com link or "set it up in Hamster"; never an invented command).

Shape: "tl;dr [skill] now runs itself. [trigger, in plain words], no hands."

`[IMG-01 — portrait or square: hero shot of the routine's OUTPUT arriving somewhere. The delivered artifact, not the config screen.]`

### 2. the pain: doing it by hand

H2 naming the repetition ("i ran this by hand every monday for four months"). 2-4 embedded posts from the source pack showing people describing the manual rhythm: the recurring invocation, the forgetting, the "every morning I paste the same prompt." One-line credibility attribution per post.

The prior-art beat here is the manual version itself:

- **Our skill**: reference the original skill article ("we shipped [skill]. then we watched what everyone did with it: the same invocation, every [cadence], by hand"). Link the skill article.
- **Third-party skill**: embed the creator's launch post, credit them by name, one line on why the skill is great. The routine extends their work; the framing is a compliment.

Zero words about the routine yet.

### 3. the personal stake

Short H2. Three or four lines tracing the consequence chain of manual repetition: not that the task is hard, but that rhythm work done by hand gets skipped, and skipped rhythm work is where drift starts. Land where the cost hits ("the week i skipped it is the week the [thing] went stale, and nobody noticed until review").

`[IMG-02 — the manual version happening: you, invoking the skill by hand, timestamp visible if possible]`

### 4. the proposal: put it on a loop

H2. Contents in order:

- One or two sentences announcing the routine ("so we made it a routine. it's a prompt with a trigger. that's the whole trick.")
- Get-it block, second appearance
- One plain-words line on the routine model: in Hamster, a routine is a prompt that fires on a schedule, on a trigger, or in a loop toward a goal. This one uses [which] because [one clause].
- Bold routine name + one line of what happens per run

`[IMG-03 — wide: the trigger configuration]`
`[IMG-04 — portrait: a completed run with its output]`

### 5. what's inside

H2, then lowercase sub-headings. For a routine the components are fixed:

**the trigger** — 1-2 sentences on the shape chosen and why the cadence/event matches when the output gets consumed. `[IMG — trigger config]`

**the prompt** — the actual autonomous prompt from the routine spec, in a code block, verbatim. This is the sauce; the reader can steal it wholesale. 1 sentence of setup max.

**a real run** — walk one run: what fired, what it read, what it produced, where it landed. `[IMG — run history]` `[IMG — the delivered output]`

**the guardrails** — 1-2 sentences on the fences (what it will not do, where the human gate sits). Trust is the product here; say it plainly.

**before/after** — the manual invocation and the run history side by side. `[IMG — the pair]` One line: "same output. nobody ran it."

### 6. other inspiration

Optional. Hat tips to adjacent automation work or the thinking that shaped the spec. One or two max.

### 7. go try it

H2. Get-it block third appearance. Then:

- Setup instruction in one line (what to point the routine at)
- The prompt again referenced ("the full prompt is above, take it")
- Two blockquoted starting points the reader can adapt:

> run [skill] against [target] every [cadence] and post the result to [place]

- CTA: tag @usehamster or @eyaltoledano with what you automated, let's riff
- `[IMG-FINAL — wide: GIF or recording of a run completing]`

### 8. (third-party mode only) the skill, upgraded

When the routine automates someone else's skill, a short section before the closer: the original skill stands on its own, here is what changes when it runs with team context in Hamster on a loop. Two or three sentences, one visual, creator credited once more. Additive, never a review.

## Format conventions

- Get-it block 3x: tl;dr, proposal, closer.
- Visual density matches the skill-article standard: a visual or code block for every claim, ~10-14 visuals typical for a routine piece (fewer components than a skill tour, but run history and before/after add shots).
- Prose ceiling: 3 sentences between visuals.
- The autonomous prompt appears in full, in a code block, exactly as specced. Never summarized.
- Blockquotes for adaptable starting points; code blocks for the verbatim prompt.
- Embedded posts: X only embeds X; Reddit finds are quoted text + link.
- Headers lowercase, casual, short.

## Voice (compact floor; full rules in hamster-content)

- No em dashes. No "not X but Y". No staccato preachy rhythm. No corporate filler. Lowercase on X.
- No "nobody talks about" openers/closers.
- Never invent mechanics, commands, trigger types, or scenarios. Never fabricate quotes or numbers. No exact follower counts.
- Consequence chain: 3 tight sentences landing where the cost hits, not 5 paragraphs.
- State it as fact, not pitch. Credit at the point of use.
- The routine framing is relief, not hustle: "it just happens now" energy, never "10x your workflow."

## Pre-delivery checklist

1. Does the pain section prove the manual repetition through real posts and/or the real prior version?
2. Trigger, prompt, and run details all traceable to the routine spec? Zero re-invention?
3. Get-it block 3x, real path or flagged placeholder?
4. Full autonomous prompt present verbatim in a code block?
5. Before/after pair in the shot list?
6. Third-party mode: creator embedded and credited at point of use?
7. Prose runs over 3 sentences anywhere?
8. Two adaptable blockquoted starting points in the closer?
9. Voice pass clean?
10. Shot list numbered and complete; gaps honest?
