# FAQ: Mapping Input Metrics From the North Star to the Work

## How many input metrics should a North Star have?

A handful. The playbook describes inputs as a small set of influential, complementary factors, and its examples use between three and five. Fewer than that often leaves a major lever out; many more makes ownership and focus hard.

## What is the difference between an input, an opportunity and an intervention?

An input is a persistent customer behavior or result that is part of the formula for the North Star and lasts quarters or years. An opportunity is a leverage point for moving an input, framed as a problem and lasting months or quarters. An intervention is concrete, time-bound work such as a feature or experiment, and it is expected to change often.

## Should every team own one input?

It can help, but it is not required. The playbook suggests letting a team or group of teams focus on a single input for an extended period once the framework is working. Early on, keep the map and the org chart separate so the structure does not decide the inputs.

## Where does technical debt go on the map?

Under a system health input, if you add one. The playbook suggests a health input for factors such as uptime, cycle time and tooling, and recommends showing non-feature work as opportunities alongside other roadmap items. That keeps it visible and comparable.

## How do we know an input really drives the North Star?

You do not know at first; each link is a belief. Check it against historical data where you can, then watch what happens when work moves the input. If the input moves and the North Star does not, revisit the link.
