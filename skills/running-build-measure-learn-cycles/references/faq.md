# FAQ: Running the Build-Measure-Learn Loop

## What is the build measure learn loop?

It is the core cycle of the lean startup. A team turns an idea into something customers can use, measures how they respond and learns whether its hypothesis holds, then decides whether to pivot or persevere. Each pass through the loop should end with a recorded lesson. The goal is to get through the loop as quickly as possible, many times.

## Why plan the loop in reverse?

Because the learning is the point. Ries plans by first deciding what to learn, then what to measure, then what to build. Starting from the build tends to produce features whose results nobody knows how to read.

## How long should a cycle be?

As short as the question allows. Some questions can be answered in days with a landing page or manual service, while others need a few weeks for customer behavior to show. Keep cycles similar in length and treat a cycle that keeps growing as a scoping problem.

## How is this different from agile sprints?

A sprint is a timebox for building work, and it can end with shipped features and no new knowledge about customers. A build-measure-learn cycle starts from a hypothesis and ends with a verdict on it. Many teams run both: sprints organize the build step inside a larger learning cycle.

## When should a cycle lead to a pivot discussion?

When several cycles on the same strategy have failed to move the key metrics, or when one core assumption keeps being contradicted. A single failed cycle usually calls for a revised hypothesis. A pattern of failures calls for the scheduled pivot or persevere meeting.
