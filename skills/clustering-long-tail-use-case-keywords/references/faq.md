# FAQ: Clustering Long-Tail Use-Case Keywords into Content Silos

## How many keywords should one cluster contain?

There is no fixed number; the test is whether one page can answer every query in it. A cluster might hold a handful of phrasings or dozens, depending on how many ways people describe the same need. If a cluster needs a table of contents to cover it, it is probably two clusters. If it holds a single query with no variants, check whether it belongs inside a neighbouring cluster.

## Should I trust keyword clustering tools?

Use them to propose groups, not to decide them. Automated clustering is fast but can merge queries with different intents or split one real cluster into several. Review every proposed group by reading the queries and asking whether one page would satisfy them all. The human review is what turns a similarity score into a usable page plan.

## What is the difference between a cluster and a silo?

A cluster is a set of queries with the same intent and use case, and it maps to one page. A silo is a set of related clusters under one parent topic, and it maps to a section of the site. Clusters decide what pages exist; silos decide how those pages are grouped, navigated and linked together.

## What do I do with long-tail queries that fit no cluster?

Put them in a review bucket first rather than forcing them into a group. If several orphans share a use case, they may form a new cluster you had not planned. If a query sits outside the subject area you want to own, move it to the dropped list with a reason. General queries with no situation attached are often better served by a hub page.

## How often should I re-cluster my keywords?

Re-run the process when you enter a new category, when your own search data shows queries you have no page for, or when community discussions reveal new use cases. Between full passes, add new queries to the existing sheet and tag them against current clusters. A full rebuild is only needed when the category structure itself changes.
