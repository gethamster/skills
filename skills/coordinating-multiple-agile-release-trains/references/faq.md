# FAQ: Coordinating Multiple ARTs with Solution Trains

## What is the difference between a solution train and an Agile Release Train?

An Agile Release Train is a team of agile teams that plans and delivers together on a shared cadence. A solution train is the coordination layer above several ARTs that are building one solution too large for any single train. It adds solution-level roles, a shared backlog of solution capabilities and cross-train integration. Each ART still runs its own planning and delivery inside that structure.

## When does an organization need a solution train?

You need one when a single solution requires more people than one train can hold and the trains depend on each other's work every PI. Signs include recurring mid-PI blockers between trains, integration that fails late, and train leads spending planning time negotiating with each other. If your trains build largely independent products, lighter coordination between train leads is usually enough.

## Who runs the solution train day to day?

Give flow facilitation to one named person, often called the solution train engineer, who runs the cross-train events and keeps the dependency board current. Pair that role with a solution content owner who sets priorities and a solution architect who owns interfaces. Write down which decisions each makes, so trains know where to escalate each kind of conflict.

## Do all trains in a solution have to use the same PI and iteration lengths?

Aligning both is strongly recommended. Shared PI boundaries let every train plan against the same priorities at the same time, and shared iteration boundaries create common integration points. Trains on different calendars turn each cross-train dependency into a scheduling negotiation. If you must transition, adjust one PI's length once at a boundary.

## How should a solution train handle dependencies on external suppliers?

Treat a supplier like another train on the dependency board: name the deliverable, the date it is needed and the person accountable on each side. Invite supplier representatives to reconciliation and integration reviews where their work is involved. Where a supplier cannot follow your cadence, plan the dependency earlier and add an explicit integration check when it arrives.
