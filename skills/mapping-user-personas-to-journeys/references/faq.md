# FAQ: Story Map Personas: Mapping Personas to User Journeys

## Do I need formal personas to build a story map?

No. Jeff Patton's quick reference suggests lightweight persona sketches, which can be a card with a name, a role and a goal. The Nielsen Norman Group describes proto personas built from the team's assumptions as a quick way to align. If you use assumptions, label them and check them against real users as soon as you can.

## How many personas should one map include?

Include the ones whose stories the product has to tell, starting with the most critical user type. Add others only as their part of the story arrives. If a map carries so many users that no single journey is complete, consider a separate map for a secondary user or feature.

## How is this different from a customer journey map?

A customer journey map records a person's experience, including thoughts, emotions and channels. A story map uses the persona's journey as its structure and fills it with what the product must do. NN/g notes that a journey map can grow into a story map when you add activities, steps and details, so the two work well in sequence.

## Where do the persona cards go on the map?

A simple layout places the primary persona at the top left and put each other persona above the columns where that user acts. Vertical lines at role changes make the hand-offs visible. Anyone looking at a column should be able to tell whose task it is.

## What if two personas need the same task done differently?

Keep one column for the shared task and hang the variations below it, labelled by persona. When slicing releases, decide which variation goes in first. If the variations are large, it may be a sign that the two users are on different journeys that deserve separate columns.
