# FAQ: Designing FAQ-Based Site Architecture for SEO

## Why one question per page instead of a single FAQ page?

A page that answers one question has an unambiguous purpose, so readers and parsers can tell exactly what it resolves. Jason Barnard's rule is one question and answer per page, with a simple answer to a simple question. A single FAQ page with many questions forces each answer to compete for the same URL and heading structure. You can still keep a hub page that lists questions and links to their individual pages.

## How short should the short answer be?

Short enough to fully resolve the question and be read on its own, and no longer. For example, a working target of two to four sentences suits most questions, but the real test is whether someone could act on it without reading further. If the answer needs a condition, include it in the answer rather than pushing it into later sections. Detail belongs in the supporting section below.

## Does FAQ schema guarantee rich results?

Nothing in this approach relies on a guaranteed display. The value of the markup here is that it forces you to think of the question and answer as a structured unit and to keep it consistent with the visible page. Treat any extra display in search as a bonus rather than the reason for doing it. Keep the markup accurate even when it is not shown.

## What should the entity home page contain?

It should state clearly who you are, what you do and which subjects you are qualified to answer questions about. Barnard suggests using a canonical URL such as your About page as the point of reconciliation for your brand. Every answer page should link to it, and nothing on the answer pages should contradict it. Update it before you publish answers in a new subject area.

## How do I stop answer pages from competing with each other?

Keep a register that maps every question to exactly one URL and check it before creating a page. Merge phrasings that would produce the same answer onto a single page. When a new page starts answering a question already owned elsewhere, move that content and link to the existing page instead.
