# FAQ: How to Write OKR Objectives

## Should an objective ever contain a number?

Usually not. The number belongs in the key results, where it can be graded, and the objective should explain what the number is for. If the objective is only meaningful as a number, it is probably a key result under some broader objective. The exception is a number that defines the end state itself and cannot be separated from it, and even then it is worth asking what the number achieves.

## How long should an objective be?

One line. Google's playbook uses that as a quick test: an objective that does not fit on one line probably is not crisp enough. Short objectives are also easier to remember, which matters because the team should be able to recall them without opening a document.

## Can an objective stay the same from one quarter to the next?

Yes. What Matters notes that an objective can be long-lived and roll over for a year or longer while its key results change as the work progresses. Aspirational objectives in particular are expected to carry forward until they are achieved. What should change each cycle is the set of key results, so the team keeps raising the bar.

## What makes an objective qualitative but still testable?

It names a concrete end state that an observer could recognize. "Resolve complex customer problems on first contact" is qualitative, yet it is clear what success would look like and what the key results should measure. "Be the best support team" is qualitative and untestable, because nothing would show whether it happened.

## Is it acceptable for an objective to sound inspiring?

It is encouraged, as long as it stays concrete. What Matters lists inspirational as one of the four qualities of a good objective, alongside significant, concrete and action-oriented. The risk is slogans that could belong to any team in any year. Use the team's own language, and keep the end state specific.
